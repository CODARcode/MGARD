# MGARD 1.7.0 Release Notes

**Released:** Unreleased

## Added
* ***HP-MDR***: a high-performance MDR-X refactoring and reconstruction pipeline, including batched bitplane (BP) encoders (v1b/v2a/OptV1), negabinary encoding, run-length encoding, adaptive and hybrid lossless compression for MDR, improved domain decomposition, better output-size estimation, and a QoI-guided progressive retrieval pipeline.
* ***BlockMGARD***: a block-based hybrid hierarchy compression pipeline with in-cache block refactoring (1D/2D/3D), region-of-interest (RoI) support, L2/L-infinity error bound control, and kernel-fusion optimizations.
* A symbol-alphabet rANS lossless backend for mgard-x, beating Huffman's compression ratio.
* A BlockDelta (FLE-based) lossless backend for mgard-x, as a Huffman alternative.
* A portable, warp-cooperative LZ4 implementation for mgard-x, removing the nvcomp dependency.
* Blackwell (sm_120) GPU build support.
* Decompression of data compressed by MGARD 1.6.x and earlier, through a separate MGARD 1.6.0-compatible decompression pipeline enabled with the new CMake option `MGARD_ENABLE_DATA_COMPATIBILITY` (default OFF). Decompression detects the version from the header and routes 1.6.x data automatically; output matches MGARD 1.6.0 (bit-identical on CPUs). Builds without the option report such data with the new status `DataCompatibilityNotEnabledFailure`.
* Generic block domain decomposition with two modes (`Config::domain_decomposition_mode`): `Auto` (default) decomposes only when the data does not fit the memory limit and picks the block size, and `Manual` uses a user-given block shape (`Config::domain_decomposition_block_size`), which may differ per dimension. Available in the `mgard-x` and `mdr-x` CLIs as `-dd auto|manual` and `-dd-size`.
* `MemoryManager::Copy3D` in RuntimeX (native 3D copies on CUDA and HIP), used for copying blocks between host and device in fewer transfers.
* Opt-in ZSTD compression of MDR-X bitplane groups (`lossless = Huffman_Zstd`; `mdr-x -l huffman-zstd`).
* Additional unit tests: bitplane encoders, DirectInterleaver, MGARDDecomposer, HybridLevelCompressor, and ComposedRefactor/Reconstructor; unit tests are now discoverable by CTest.

## Changed
* Deprecated and removed the legacy standalone MGARD-CUDA backend in favor of ***MGARD-X***.
* Restructured the original MGARD CPU source tree under a dedicated `mgard` directory, and reorganized unit tests.
* Replaced `exit()` calls with C++ exceptions for internal errors across mgard-x.
* Optimized the Huffman compress/decompress pipeline (roughly 1.9x faster compression).
* Bumped the bundled ZSTD to v1.5.6 and protobuf to v3.21.12; stopped building nvcomp.
* Raised the minimum ROCm requirement to 7.0 for HIP builds.
* ***Breaking (API):*** replaced the MaxDim/Block/Variable domain decomposition types with the generic block decomposition. `Config::domain_decomposition`, `block_size`, `domain_decomposition_dim` and `domain_decomposition_sizes` are removed in favor of `domain_decomposition_mode` and `domain_decomposition_block_size`; variable-size decomposition is no longer supported. The CLIs' `-dd max-dim|block` became `-dd auto|manual`. Compressed data with the previous MaxDim and Block decomposition headers still decompresses.
* ***Breaking (API):*** merged `max_larget_level` into `num_global_refactoring_level`, which now caps the levels of every multilevel hierarchy (multi-dimensional, MDR-X, and the hybrid global stage) and is recorded in the compressed header. Defaults are `num_local_refactoring_level = 1` and `num_global_refactoring_level = 3` (previously all levels for multi-dimensional compression). This changes the default compression ratio (e.g. relative 1e-3, L-infinity: 1D 2.89 -> 3.44, 3D 2.57 -> 2.85; L2 in 1D: 4.08 -> 3.65); error bounds are unchanged.
* Renamed `MemoryManager::CopyND` to `Copy2D` in RuntimeX.
* Reduced mgard-x memory usage: hierarchy level volumes are stored per level instead of in a dense array, hierarchies are moved rather than copied into the compressor and refactor caches, and the hybrid hierarchy builds only the global hierarchy it needs (new `HybridHierarchy`). Peak device memory for a 2^24-element 1D float input drops from 7.7 GB to 1.8 GB (multi-dimensional) and 2.1 GB (hybrid).
* MPI is now optional for `MGARD_ENABLE_MDR`; only the `pmdr-x-qoi` and `pmdr-x-qoi-io` executables require it.
* The MDR-X QoI executables always use one subdomain per variable and no longer take `-dd`.
* Updated documentation: the MGARD-X guide for the hybrid hierarchy pipeline, a hybrid RoI user guide, the MGARD family tree, performance figures, and the publications list.

## Fixed
* Fixed an MDR-X sign-buffer heap overflow in bitplane decoding.
* Fixed uninitialized padding in ComposedRefactor level buffers.
* Fixed MaxErrorEstimatorHB missing a negabinary error margin.
* Fixed a stale active-device bug in the CUDA/HIP DeviceSpecification and DeviceQueues.
* Fixed stale leading dimensions on Array shrink.
* Fixed GreedyBasedSizeInterpreter fetching more bitplanes than necessary.
* Fixed a floating-point exception in Zstd::Decompress.
* Fixed CPUPipelines so OpenMP-only builds compile again.
* Fixed clang-format violations flagged by CI.
* Fixed decompression of domain-decomposed data in which a subdomain stored uncompressed has a size that is not a multiple of 8 bytes: the following subdomains were read at the wrong offset.
* Fixed an MDR-X sign-buffer overflow in bitplane decoding during reconstruction (heap corruption on CPUs, out-of-bounds writes on GPUs) when a later subdomain needed a larger buffer.
* Fixed MDR-X reconstruction writing back the last subdomain from the wrong buffer when the number of subdomains is a multiple of 3.
* Fixed MDR-X refactoring/reconstruction sizing reused buffers from the first subdomain instead of the largest.
* Fixed MaxDim domain decomposition along a dimension other than the slowest, which copied past the end of the data.
* Fixed Zstd decompression truncating the stored size to 32 bits and ignoring decompression errors.
* Fixed the compression output buffer overflowing for non-uniform grids, whose coordinates are stored in the header.
* Fixed the `mgard-x` CLI ignoring decompression failures.
* Fixed MDR-X requests fetching a full bitplane group for levels that need none, and stale bitplane counts when a reconstructor is reused.
* Fixed the Huffman compression-ratio estimate pairing frequencies with the wrong code lengths, which made MDR-X store compressible bitplane groups uncompressed.
* Fixed CPU (MGARD) Huffman truncation of wide outliers.
